## 0.23.0 - 2026-08-24

- **Derive arrays: `Vec<T>` of schema types is `Shape::Array`** ([#106](https://github.com/arthur-debert/clapfig/issues/106), [#132](https://github.com/arthur-debert/clapfig/issues/132), DER01-WS03) — `#[derive(clapfig::Schema)]` now supports arrays of nested schema types end to end; the old compile-time rejection ("Vec\<NestedStruct\> is not yet supported") is gone.
  - `Vec<NestedStruct>` emits the structural `FieldStatic::ArrayOf`, converted to a runtime `Shape::Array` of the nested object (TOML `[[name]]`): typed loading into `Vec<T>`, per-entry defaults, per-entry required/type checks and strict unknown-key detection with indexed paths (`plugins[1].rogue`), commented array-of-tables template example, and JSON Schema `items` all work through the existing walkers. `FieldStatic::ArrayOf` is a struct variant carrying the field-site `///` doc (parity with `Nested`/`MapOf`).
  - Support is **trait-resolved, not syntactic**: the macro emits `<T as Schema>::STATIC` and the *compiler* decides whether the element type qualifies — any type deriving `Schema` works, and a non-qualifying element (`Vec<PathBuf>`) fails with the trait's `on_unimplemented` guidance naming the `#[clapfig(value)]` escape hatch.
  - Enum-vs-object distinction: `Vec<UnitEnum>` flattens converter-side to `Shape::Array` of an enum leaf — the array sibling of WS02's map-of-enum flatten — so entries validate against the variant set, the template emits the `# Allowed:` line, and the JSON Schema carries `enum` on the `items` schema. This lands the mechanism behind the postponed #101/#102.
  - `Option<Vec<UnitEnum>>` keeps the presence signal (absent → `None`). `Option<Vec<NestedStruct>>` has no representation (absence is already the empty array) and fails at the first `schema()` call with drop-the-`Option` guidance — deferred like the other enum-vs-struct kind checks, since the macro cannot resolve the element kind.
  - Absence rule unified with maps (**behavior change**): an absent array is the empty array. Non-optional `Shape::Array` nodes without a declared default — arrays of objects and plain `Vec<String>`-style scalar arrays alike (the latter previously a `MissingRequired` error) — now materialize `[]` before the typed deserialize, and array fields are no longer listed as `required` in the generated JSON Schema. Templates use the same rule: a non-optional array or map field no longer carries a `Required.` line (absence is already `[]`/`{}`). A declared `#[clapfig(default = [...])]` still wins over the empty-array materialization.
  - Defaults on array-of-nested fields are rejected at derive time (same rule and rationale as map-of-nested fields: entries are user-supplied), as are `env`/`allowed`/`optional`. Remaining unsupported constructs (`Vec<Vec<...>>`, `Vec<Option<T>>`, `Vec<clapfig::value::Value>`, maps of arrays of schema types) keep derive-time errors naming the `#[clapfig(value)]` escape hatch.
- **Derive hardening: silent-wrong `#[derive(clapfig::Schema)]` behaviors fixed or rejected** ([#131](https://github.com/arthur-debert/clapfig/issues/131), DER01-WS02) — Every audited case where the derive compiled but produced a schema that disagreed with serde or lost information is now either correct or a derive-time error. **Breaking on purpose**: code relying on the newly-rejected constructs was already silently misbehaving; there is no compatibility path.
  - Fixed: `HashMap<String, UnitEnum>` / `BTreeMap<String, UnitEnum>` now flattens to `Shape::Map` of an enum leaf — previously it emitted a map of an empty schema and every entry failed at load with "expected map, got string" (map-shaped sibling of the `Nested` enum flatten).
  - Fixed: raw identifiers unraw — a field `r#type` (or variant `r#Try`) now emits serde's spelling (`type`/`Try`) instead of `r#type`, which no config key could ever match.
  - Fixed: field-site `///` docs on bare nested-struct, unit-enum, and map-of-nested fields are retained (field doc wins over the referenced type's doc; previously dropped, asymmetric with `Option<Enum>`). `FieldStatic::Nested`/`MapOf` are now struct variants carrying the field-site doc.
  - Fixed: `Vec<clapfig::value::Datetime>` array defaults emit datetime-typed elements (previously string-typed, rejected by the leaf's own type check at first `schema()` call).
  - New derive-time errors: duplicate schema field names after renames; invalid rename strings (empty, or containing `.`/`[`/`]`); unknown `#[clapfig(...)]` metas on enum variants (previously silently skipped); conflicting variant-level clapfig/serde renames (previously clapfig silently won); `#[clapfig(name)]`/`#[clapfig(strict)]` on unit-only enums (accepted then discarded at flatten); kind-mismatched `default` literals (checked like `allowed`, per element for arrays, and against the `allowed` set when both are present); defaults on map-typed fields.
  - Reject-loudly serde policy (epic DER01 decision): every serde attribute the schema does not honor — `default`, `flatten`, `alias`, `skip`, `skip_deserializing`, `untagged`/`content` and adjacent tagging, `deny_unknown_fields`, `transparent`, `from`/`try_from`, … — is a derive-time error naming the attribute and the divergence it would cause. Honored and serialize-only/plumbing attributes (`rename`, unit-enum `rename_all`, internal `tag = "..."` on enums (see `unreleased-shape-algebra-tagged-derive.md`), `deserialize_with`/`with`, `skip_serializing*`, `serialize_with`, `bound`, `borrow`, `crate`, `expecting`) remain accepted.
  - Lookalike guard: field types merely *named* `Datetime`/`Value` are claimed by name (a proc macro can't resolve paths), so the derive now emits a compile-time `IsClapfigDatetime`/`IsClapfigValue` assertion — a user's own `struct Datetime` is a compile error with guidance instead of a silently mis-typed datetime leaf.
  - Enum-typed field defaults (`#[clapfig(default = "variant")] mode: Mode`) are checked against the variant set at first `schema()` call; a non-variant default panics with a message naming the field and the variant list.
  - Diagnostics: the `clapfig::Schema` trait carries `#[diagnostic::on_unimplemented]`, so unsupported field types (PathBuf, Duration, char, newtypes, …) produce a message naming the supported scalar set and the `#[clapfig(value)]` escape hatch instead of a raw E0277.
  - Fixed (review round): absent maps load as the empty map on the typed path. Non-optional `Shape::Map` nodes — bare `HashMap<String, scalar>`, the flattened map-of-enum, and maps of structs — materialize `{}` before the typed deserialize — previously absence was a `MissingRequired` or serde missing-field error, contradicting the derive's own "an absent map is already the empty map" guidance. `Option<Map<..>>` still loads as `None`. Map fields are no longer listed as `required` in the generated JSON Schema.

- **Changed**
  - **Runtime UX sweep: templates, error rendering, JSON Schema fidelity, integer bounds** ([#134](https://github.com/arthur-debert/clapfig/issues/134), part of DER01 [#129](https://github.com/arthur-debert/clapfig/issues/129)) —
    - **Templates (`config gen`)**: required-defaultless leaves carry a `Required.` annotation in all three formats (previously they rendered identically to optional placeholders, so users generated a template, didn't uncomment, and failed with `MissingRequired`); array/map placeholders (`[]`/`{}`) carry an `Elements:`/`Values:` element-type hint.
    - **Integer-for-float coercion**: `timeout = 5` on an `f64` field loads (serde always accepted it; the schema check no longer rejects it first). The merged value is coerced to `Value::Float` during finalization — schema-driven, like the ADR-0001 datetime coercion — so Map-out consumers and `config get` see a float too (`schema_walk::coerce_datetime_value` is now `coerce_value`).
    - **Error rendering**: YAML/JSON unknown-key errors no longer render a bogus `(line 0)` / `--> config.yaml:0` (the line is omitted when it can't be located; real YAML/JSON line numbers landed in PRV01). Env-derived unknown keys render as env errors naming the exact variable to unset (`MYAPP__ROGUE_KEY`) instead of wearing config-file clothing — `UnknownKeyInfo` gains `env_var: Option<String>`, and `on_unknown_key` callbacks now see `file: None` for env-sourced keys (previously a synthesized `<env>` path). Omitting `Layer::Env` from `layer_order` skips env construction and unknown-key validation, so `APP__ROGUE` no longer fails when the env layer is excluded. A deserialize failure inside a typed `post_validate` hook is categorized as the `InvalidValue` type error it is, not `PostValidationFailed` wearing a bare serde message — on `load`/`TypedResolver` and on merged `config get`/`list` via typed `handle`. `KeyNotFound` is now a struct variant carrying an optional near-miss `suggestion` (`Key not found: db.pool_sizr — did you mean 'db.pool_size'?`; new public `meta::nearest_key`). Scoped `config get` against a scope whose file doesn't exist fails as the new `ScopeFileMissing { scope, path }` instead of claiming the key doesn't exist.
    - **JSON Schema export**: leaf-container conversion is recursive — nested arrays keep inner `items`, `Array(Enum)` keeps the enum constraint on items, `Map(elem)` constrains entry values via `additionalProperties` (with the ADR-0002 `^//` comment-key allowlist). `required` now mirrors what the runtime rejects when absent: a leaf only if non-optional AND defaultless, a section only if it transitively contains one (previously every section and every non-optional leaf was required, so external validators rejected configs clapfig loads fine). Datetime leaves export `type: string` plus an `anyOf` covering TOML's four lexical forms: range-aware patterns (month/day/hour/minute/second/offset) so `1979-99-99` is not accepted, with `format: "date-time"` / `"date"` only on the branches those formats describe; datetime defaults emit in lexical string form instead of being dropped. Heterogeneous `Enum` sets omit a single inferred `type` so `enum` alone constrains mixed primitives. Unrepresentable values (non-finite floats — JSON has no literal for them) omit the complete `default` / `enum` annotation rather than dropping individual members and exporting a narrowed set.
    - **Integer bounds**: `LeafType::Integer` / `LeafTypeStatic::Integer` carry `min`/`max` bounds; the derive macro emits each Rust width's range (`u8` → `0..=255`; `i64` unbounded; `isize` uses `isize::MIN/MAX as i64`; `u64` min 0, open top; `usize` min 0 with a maximum only when `usize::BITS < 64`), the runtime check rejects out-of-range values naming the key path (`u8 = 300` no longer sails through to a `<merged>` serde failure), and the JSON Schema export carries the bounds as `minimum`/`maximum`. New runtime builder `Field::integer_in(min, max)` (panics if both ends are set and `min > max` — an authoring error, same class as a duplicate field name).
- **Changed**
  - **Structural collapse of the two-path era + hard rename sweep** ([#130](https://github.com/arthur-debert/clapfig/issues/130), part of DER01 [#129](https://github.com/arthur-debert/clapfig/issues/129)) — The crate has one schema model (`runtime::Schema`); the bridge-era mirror that half the code still walked is gone. Internally: the `SchemaRef`/`FieldRef`/`FieldKindRef`/`LeafRef` view types and the single-implementation `ConfigSpec` trait (with its `DynamicSpec` newtype) are deleted; every consumer — metadata lookup, JSON Schema emission, strictness cascade seeding, valid-key enumeration, unknown-key validation — walks the one schema model directly (as of SHP01 the node walked is `Shape`; `Schema` stays the object constructor), and the resolve pipeline holds the schema instead of a generic spec. The two ~65-line unknown-key walkers (per-file and env-layer) are now one walker serving both layers; the env layer gains harmless array-of-objects recursion (env dotted keys can't build arrays-of-tables, so no behavior change). Pure structural collapse: behavior unchanged except the renames below (pre-1.0, no aliases per project rule). Public renames, on the Map-out vs typed-out axis (bare name = Map-out, `Typed` prefix = typed-out):
    - `RuntimeBuilder` → `Builder`; entry point `Clapfig::runtime(schema)` → `Clapfig::builder(schema)`
    - `RuntimeResolver` → `Resolver`
    - `SchemaConfigBuilder<C>` → `TypedBuilder<C>`; entry point `Clapfig::schema_builder::<C>()` → `Clapfig::typed::<C>()`
    - `meta::doc_for_runtime` → `meta::doc_for`
    - module `clapfig::schema` → `clapfig::json_schema` (the JSON Schema emitter; "schema" alone collided with the derive trait and the data model)
- **Struct-level `rename_all` in `#[derive(clapfig::Schema)]`** ([#107](https://github.com/arthur-debert/clapfig/issues/107), [#133](https://github.com/arthur-debert/clapfig/issues/133), DER01-WS04) — `#[serde(rename_all = "...")]` / `#[clapfig(rename_all = "...")]` on a struct is now honored instead of rejected: the derived schema converts every field name (fields without an explicit rename) with serde-exact semantics — `serde_derive`'s `RenameRule::apply_to_field`, snake_case source — so schema names, strict validation, templates, and JSON Schema all use the converted spellings, and with the serde spelling (or a matching pair) the typed deserialize agrees too. The clapfig spelling alone converts the schema only — it cannot change serde's generated `Deserialize` — so it's meant for schema-only types; typed structs should use `#[serde(rename_all)]`. Full rule set: `lowercase`, `UPPERCASE`, `PascalCase`, `camelCase`, `snake_case`, `SCREAMING_SNAKE_CASE`, `kebab-case`, `SCREAMING-KEBAB-CASE`, including serde's digit behavior (`render_2d` → `Render2d`) and identity `lowercase`/`snake_case`.
  - Precedence matches serde: explicit `#[clapfig(rename)]`/`#[serde(rename)]` wins over the rule; a serialize-only directional field rename is invisible to the deserialize side, so the rule still applies there. The directional `rename_all(deserialize = "...")` form contributes its deserialize rule; a serialize-only `rename_all(serialize = "...")` stays accepted and inert.
  - Converted names run through the same derive-time validation as explicit renames (non-empty, no `.`/`[`/`]`) and the post-rename duplicate check.
  - New derive-time errors: an unsupported rule string (lists the supported set), and a clapfig/serde `rename_all` pair naming different rules (same contract as conflicting field renames). Unit-only enums use the same two-spelling conflict check (including serde's directional `rename_all(deserialize = "...")` form) so a clapfig/serde pair cannot silently convert variant names one way and deserialize the other.
  - Boundary: a `kebab-case` schema is incompatible with the builder's `normalize_keys(true)` mode (which canonicalizes incoming keys to snake_case) — the combination fails strict validation loudly rather than silently mis-loading; pick one convention.
- **Editor-discoverable artifact pair** ([#103](https://github.com/arthur-debert/clapfig/issues/103)) — `Builder::artifacts(&options)` (and its `TypedBuilder` twin) renders the config template and its JSON Schema document from the one `Shape` the builder holds, and can prefix the template with the editor schema directive a TOML language server reads to validate a config file as the user types it. Additive: `ConfigAction::Gen`'s fields are unchanged and there is no new CLI behavior.

  - **The pair.** `ConfigArtifacts { template, schema }`, returned as strings — clapfig writes nothing. The template body is what `config gen` renders in the preferred format; the schema text is what `config schema` emits. Both entry points have the method (runtime `Shape` and `#[derive(Schema)]`), and both generate from the same schema.
  - **The directive.** With a reference set, the template's first line is exactly `#:schema <reference>` and a blank line separates it from the body. It is an ordinary TOML comment, so a file carrying it loads and strict-validates as before.
  - **The reference is the caller's.** `SchemaReference::new` validates one line — rejecting empty, whitespace-only, line-break-carrying, control-character-carrying, and surrounding-whitespace values as `ClapfigError::InvalidSchemaReference` — and is otherwise opaque: no path resolution, no reachability check, no reference inferred from an output path. The caller owns the path or URL, the filesystem layout, writing both files, and publication/versioning.
  - **Format capability** (ADR-0002 matrix row `Operation::SchemaDirective`). TOML declares it; YAML and JSON do not, so asking for a reference under either refuses with the typed `UnsupportedByFormat` error instead of dropping the binding. No JSON `$schema` member and no YAML language-server comment.
  - **`normalize_keys` reaches the JSON Schema.** With `.normalize_keys(true)`, `config schema` and the pair's schema name every multiword key twice — the kebab-case spelling the template writes (`pool-size`) and the declared snake_case one (`pool_size`) — because that builder loads either. Object schemas are closed, so a document naming just one spelling would make an external validator reject a file clapfig reads: the template beside it, or a hand-written snake_case config. A key written under both spellings at once is rejected, the way the load path refuses that collision. Applies to nested and map-entry fields and to tagged tag keys and variant fields; discriminator values, doc comments, and defaults are unchanged.
  - **The one pairing that refuses.** A schema *declaring* a key that already holds a `-` (`rename_all = "kebab-case"`, `SCREAMING-KEBAB-CASE`, an explicit rename) is unreachable under `.normalize_keys(true)`: normalization rewrites the `-` to `_` before validation, so no written spelling matches the declared name and loading already fails every document. Everything that generates under those names now refuses that combination with the new `ClapfigError::UnreachableNormalizedKey`, naming the key, its section, and the spelling it arrives under, instead of emitting a template or schema under names the same builder's loader rejects: `config gen`, `config schema`, `artifacts()`, and `config set` against a scope file that does not exist yet — that set seeds the file from the same template generator, and is refused before it writes anything, so no file is left behind (a `config set` editing an existing file never generates and is unaffected). Checked at every depth — nested fields, array and map entry fields, tagged tag keys and variant fields. Either supported pairing is untouched: a kebab-declared schema without normalization, and normalization over a snake_case one.
  - **Opt-out is the default.** Without a reference, template and schema are byte-for-byte the standalone actions' output.
  - **Consumer proof.** `bin/tombi-proof.sh` generates an edward-shaped pair through the `schema_directive` example and runs a pinned tombi against it: the template validates, a filled-in instance validates under either spelling of its multiword key, and both spellings at once — as well as an unknown key — are rejected.
- **Provenance contract** ([#147](https://github.com/arthur-debert/clapfig/issues/147), epic [#146](https://github.com/arthur-debert/clapfig/issues/146)) — public error types grow origin facts. Hard cut, no shims (per project policy).

  - **`FormatAdapter::parse` returns `{ value, spans }`** (`clapfig::format::Parsed`): the value tree and a path → `SpanEntry` index together (ADR-0005). `FormatAdapter::span_index` and `Operation::SpanIndex` are gone. Each index entry is `{ key: Option<Span>, value: Span }` (ADR-0006); `key` is `None` on array elements. Shipped adapters (TOML, YAML, JSON) fill the index; dummy/test adapters and persist callers that only need the tree still return an empty map via `Parsed::from_value`. Callers that only want the tree use `.value`.
  - **`PathSegment::Index` is back on `ConfigPath`**, with `ConfigPath::index(n)` next to `.key(...)`. Display is one-way: dotted keys, `[n]` indexes, quoted non-bare keys (`plugins[3].host`, `"a.b"` vs `a.b`). File-edit adapters refuse a persist path that contains an array index (`FormatError::Edit`) rather than silently dropping the index and editing a different location.
  - **`ClapfigError::InvalidValue`** gains `origin: Box<OriginFacts>` (file, span, env var, URL query key, `input_type`). **`UnknownKeyInfo`**, **`UnknownKeyContext`**, and **`CollectedUnknown`** gain the same facts as flattened fields (`span`, `url_key`, `input_type`; `env_var` was already on `UnknownKeyInfo`). `InputType` is `File` / `Env` / `Url` / `Override` / `Default` — not [`Layer`](https://docs.rs/clapfig/latest/clapfig/enum.Layer.html). Later slices fill file spans, `InvalidValue.origin`, and `MissingRequired` discovery. Unknown-key `input_type` and `url_key` remain unset on the unknown-key walk (env-derived keys already name `env_var`). The `InvalidValue` facts are boxed so `ClapfigError` stays a small `Result` error.
  - **`ClapfigError::MissingRequired`** gains a `discovery: DiscoveryRecord` field (file probes with `loaded` / `missing` / `error` / `not probed` outcomes, plus which non-file input types were consulted). It does **not** gain an origin — an absent key has none. The discovery slice fills the record.

  **Migration (hard cut, per project policy):**

  - `adapter.parse(text)` is now `Result<Parsed, FormatError>`. Use `parsed.value` (or `adapter.parse(text)?.value`) wherever you previously used the `Value`. Dummy/test adapters that do not fill spans construct `Parsed::from_value(value)` (public).
  - Struct-update / match arms that name `InvalidValue { key, reason }`, `MissingRequired { key }`, `UnknownKeyInfo { ... }`, `UnknownKeyContext { ... }`, or `CollectedUnknown { ... }` must include the new fields or `..`. `ClapfigError` remains `#[non_exhaustive]`.
  - Do not match `Operation::SpanIndex` or call `span_index`; those entry points no longer exist.
- **Provenance discovery** ([#152](https://github.com/arthur-debert/clapfig/issues/152), epic [#146](https://github.com/arthur-debert/clapfig/issues/146)) — `ClapfigError::MissingRequired` now carries the filled discovery record of the search that did not find the key. An absent key has no winning origin (including a nested leaf whose parent map exists).

  - File probes report `loaded` / `missing` / `error` / `not probed`. Under `SearchMode::FirstMatch`, candidates the search never reached are `not probed`, not `missing`. Under `SearchMode::Merge`, every candidate is probed: hits are `loaded`, misses are `missing`. Stem-based discovery names the paths actually probed (each enabled extension in a directory), not a dump of the format registry. Omitting `Layer::Files` from `layer_order` skips file discovery: no I/O, and `MissingRequired` lists no file probes (the files layer was not consulted). Production I/O failures still abort as `ClapfigError::IoError` rather than a probe `error` outcome — an unreadable file is not a missing-key search.
  - Non-file input types consulted (env unless `.no_env()` or `Layer::Env` omitted, URL when a query was supplied and `Layer::Url` is in the order, programmatic overrides when any were supplied and `Layer::Cli` is in the order) are listed on the same record. Omitting `Layer::Env` also skips capturing `std::env::vars()` at `build_resolver` (that iterator panics on a non-Unicode variable). - **The JSON format adapter** ([#114](https://github.com/arthur-debert/clapfig/issues/114), epic [#110](https://github.com/arthur-debert/clapfig/issues/110)) — JSON is now a fully working config format behind the `clapfig::format` contract: enable it with `.formats([... , "json"])` / `.file_name("myapp.json")`, or hit it via any explicit `.json` path (`gen --output`, persist scopes). Parsing (`serde_json`), documented template generation, serialization, and `config set`/`unset` editing all work, with the format-parity suite locking that a JSON config resolves to the identical value tree, identical validation errors, and identical exported JSON Schema as its TOML spelling. Per ADR-0002:

  - **Comments via the `"//"` key convention**: generated JSON templates carry documentation as `"//"`-keyed members (one `"//"` per object for its prose, `"//field-name"` for per-field docs, arrays of strings for multi-line text; defaultless fields show their assignment snippet inside the comment, JSON's counterpart of a commented-out TOML line). The adapter strips every `//`-prefixed member at parse time, before the value tree exists — so comment keys never meet schema validation, and the `//` key namespace in JSON config files is **reserved**: such a member is a comment at any nesting depth and can no longer be a configuration key (hard cut, per project policy). The reservation is enforced at every outgoing boundary too — serializing a map with a `//`-prefixed key, rendering a template for a `//`-prefixed schema field, or editing through a `//`-prefixed path is a typed error, never text the next parse silently strips.
  - **Exported JSON Schema allowlists comment keys**: every emitted object (including map-of entry containers) carries `patternProperties: {"^//": {}}` beside `additionalProperties: false`, so third-party validators accept documented templates. Clapfig's own validation is unaffected — it never sees the keys.
  - **Edits preserve comments as data**: `config set`/`unset` on a JSON file keeps every `"//"` member and the document's key order, because comments are ordinary members; a newly created key whose `"//key"` comment already exists (a template's defaultless field) lands right after that comment, keeping documentation adjacent. Untouched numbers keep their exact lexical form across edits. Formatting is normalized on edit (pretty-printed, two-space indent) — the documented, expected behavior. Missing files are seeded from the documented template.
  - **Baseline mapping errors are typed and name the key**: `null` (absence expresses unset — omit the key), integer literals outside `i64` on either side (`serde_json`'s `arbitrary_precision` keeps the lexical form, so above-`i64::MAX` and below-`i64::MIN` literals are both caught — never a silent float), float literals overflowing `f64`, and serializing a non-finite float (JSON has no literal for it) each produce a typed error instead of silent coercion.
  - **`normalize_keys(true)` reaches every format structurally**: template generation renames schema fields to kebab-case before rendering, so JSON object keys, `"//field"` comment keys, and assignment snippets come out kebab-case — the previous TOML-only textual rewrite is gone.
  - **Datetimes ride as strings** in TOML's four lexical forms and land in the owned `Datetime` variant via the schema-driven coercion pass (ADR-0001) — a JSON config resolves datetime-for-datetime identical to its TOML spelling.
- **`normalize_keys` reaches the persistence path** ([#122](https://github.com/arthur-debert/clapfig/issues/122)) — with `.normalize_keys(true)`, `config get` (merged and scoped), `config set`, and `unset` apply the same dash/underscore key equivalence the file, CLI, and URL layers already did, across TOML, YAML, and JSON. Previously the persistence path ignored the setting: a kebab-case action key failed the snake_case valid-keys check as `KeyNotFound`, a missing scope file was seeded with normalization hardcoded off, and setting a snake_case key against a kebab-case document created a duplicate sibling that failed the next load with `NormalizedKeyCollision`.

  - The action key is normalized to the canonical snake_case path before the valid-keys and leaf-type checks, so `config set pool-size 10` and `config set pool_size 10` address the same leaf; merged and scoped `config get` accept either spelling the same way.
  - Edits preserve the spelling a document already uses: each path segment resolves by dash/underscore equivalence (exact spelling preferred), so a set against a kebab-case document edits `pool-size` in place instead of creating a `pool_size` sibling. Segments the document does not contain are written kebab-case.
  - A missing scope file that `config set` must create is seeded from the normalized template, so a seeded file and `config gen` agree on key spelling.
  - A document that already spells one key both ways is ambiguous about which occurrence an edit should touch, so the edit refuses with `NormalizedKeyCollision` — the same refusal the load path gives that document.
  - With `normalize_keys` off (the default), every persistence path keeps the exact-spelling behavior.
- **The pipeline swap: clapfig speaks its own value model** ([#112](https://github.com/arthur-debert/clapfig/issues/112), epic [#110](https://github.com/arthur-debert/clapfig/issues/110)) — The core pipeline (layer construction, merge, defaults, validation, resolved output, schema defaults/enum sets) now traffics in the owned `clapfig::value::Value` / `clapfig::value::Map` model; `toml`/`toml_edit` are confined to the TOML format adapter behind the `clapfig::format` contract. Every file read and write — discovery parsing, template generation, persistence edits, file seeding — dispatches through the adapter registry. TOML-path behavior is regression-locked (generated templates are byte-identical, golden-tested); the refactor is invisible unless you touch one of the renamed public types below. Also new, per the value-model spec:

  - **Builder file contract**: `.file_name("myapp.toml")` keeps exact-name discovery (that name's format only; extensionless names still parse as TOML). New `.file_stem("myapp")` + `.formats(["toml", ...])` probe the stem across the enabled formats' extensions — ordered, opt-in, default TOML only; two same-stem files in one directory are a hard `AmbiguousConfigFiles` error, and an empty or repeating `formats(...)` list is a hard `InvalidFormats` error. The first enabled format is the preferred format: stdout `config gen` renders it, and file-creating `config set` seeds `<stem>.<preferred extension>` from the template. Explicit paths (persist targets, `gen --output`) select their adapter by extension, independent of the enabled list; a file name or explicit path with an extension no adapter claims (e.g. `config.ini`) is a hard `UnknownFormat` error — never a silent TOML fallback.
  - **Typed refusals name the attempted operation**: a `config set` refused by a format reports the capability-matrix row actually attempted — replacing an existing value, creating a missing key, or creating a missing file (`clapfig::format::SetTarget`, classified at the persist boundary from whether the file and the key exist) — instead of labelling every set "replacing an existing value".
  - **Schema-driven datetime coercion** (ADR-0001): for leaves declared `DateTime`, string values from schema-blind sources (env vars, CLI/URL overrides, `config set`, future YAML/JSON files) are parsed against TOML's four datetime lexical forms; a string matching none of them is a normal type error. Never value-sniffing — only declared datetime leaves coerce.
  - **Hack deletions**: the derive path's serialize-reparse datetime round trip (the serde bridge deserializes `Value` directly) and the `toml_value_to_json` boundary converter (JSON Schema export converts from the owned model).

  **Migration (hard cut, per project policy):**

  Names as of later DER01-WS01: `Clapfig::runtime` → `Clapfig::builder`, `RuntimeResolver` → `Resolver`, `SchemaConfigBuilder` → `TypedBuilder`. The `resolve_at` return type is `clapfig::value::Map` either way — not `toml::Table`.

  - `Clapfig::builder(...).load()` / `load_with_unknowns()` / `Resolver::resolve_at*` return `clapfig::value::Map` (a `BTreeMap<String, clapfig::value::Value>`) instead of `toml::Table`. `Value` keeps the familiar accessors (`as_str`, `as_integer`, …) with `as_map` replacing `as_table`, plus `Index<&str>`/`Index<usize>`. Deserialize a map into a typed struct with `clapfig::value::from_value(Value::Map(map))`. The typed path's `TypedBuilder::build_resolver()` returns `TypedResolver<C>` (DER01-WS06), whose `resolve_at` deserializes that map into `C`.
  - The runtime `post_validate` hook receives `&clapfig::value::Map` instead of `&toml::Table`. (The typed `TypedBuilder::post_validate` still receives `&C`.)
  - Schema value slots — `Field::default(...)`, `Field::enum_of(...)`, `runtime::Leaf::default`, `LeafType::Enum { values }` — hold `clapfig::value::Value` instead of `toml::Value`. `From` impls keep literal call sites (`.default(8080i64)`, `.enum_of(["a", "b"])`) source-compatible.
  - Derive field types: `toml::Value` → `clapfig::value::Value` (for `#[clapfig(value)]`-style free-form leaves) and `toml::value::Datetime` → `clapfig::value::Datetime`. The derive no longer recognizes the `toml` spellings.
  - `UnknownKeyContext::value` and `CollectedUnknown::value` carry the owned `clapfig::value::Value`.
  - `ClapfigError::ParseError::source` is now the adapter's `clapfig::format::FormatError` (carrying the parse span) instead of `toml::de::Error`; `ClapfigError::parse_error()` returns it accordingly. New variants: `Format` (adapter refusals/failures outside file parsing), `UnknownFormat`, `InvalidFormats`, `AmbiguousConfigFiles` — `ClapfigError` is `#[non_exhaustive]`, so existing `match`es with a catch-all arm keep compiling.
  - `config set`/`unset` edit failures (e.g. a path conflict through an existing scalar) surface as `ClapfigError::Format` carrying the adapter's typed `FormatError`, instead of being collapsed into `InvalidValue`; `InvalidValue` remains the schema/type-validation error.
  - `static_schema::ValueStatic::to_toml()` → `to_value()`, returning `clapfig::value::Value`.
- **YAML format adapter** ([#113](https://github.com/arthur-debert/clapfig/issues/113), epic [#110](https://github.com/arthur-debert/clapfig/issues/110)) — The YAML adapter is implemented end to end behind the `clapfig::format` contract: enable it with `.formats(["toml", "yaml"])` (extensions `.yaml`/`.yml`) and a `config.yaml` participates in discovery, resolution, validation, `config gen`, and `config set`/`unset` exactly like TOML — the parity suite locks identical resolved trees, identical validation errors, and an identical JSON Schema for the same logical config.

  - **Parsing** (`serde_norway`, ADR-0003): strict scalars — only `true`/`false` are booleans, so `country: no` stays a string (no Norway problem); anchors/aliases resolve invisibly; custom tags, merge keys (`<<`), `null`/`~`, non-string mapping keys, and integers outside `i64` are typed errors naming the offending key; `.inf`/`.nan` parse into non-finite floats; an empty or comments-only file is the empty config. Datetimes ride as strings in TOML's four lexical forms and become `Value::Datetime` via the schema-driven coercion pass (ADR-0001).
  - **Templates**: `config gen` renders a documented YAML template with native comments — defaults live, defaultless leaves as commented placeholders, sections with no defaults commented entirely so the template always parses clean.
  - **Editing** (`yamlpath` + `yamlpatch`, ADR-0003): `config set`/`unset` are targeted span patches, byte-preserving outside the edited span — comments and formatting elsewhere survive. Every edit is verified to reparse to exactly the intended tree; shapes the patch stack cannot rewrite honestly (sequence-item edits, list appends, flow-collection members whose surgery would drop siblings) refuse with the typed `UnsupportedByFormat` error instead of corrupting the file.
