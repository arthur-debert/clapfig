- **Derive arrays: `Vec<T>` of schema types emits `Field::ArrayOf`** ([#106](https://github.com/arthur-debert/clapfig/issues/106), [#132](https://github.com/arthur-debert/clapfig/issues/132), DER01-WS03) — `#[derive(clapfig::Schema)]` now supports arrays of nested schema types end to end; the old compile-time rejection ("Vec\<NestedStruct\> is not yet supported") is gone.
  - `Vec<NestedStruct>` emits the structural `FieldStatic::ArrayOf` → runtime `Field::ArrayOf` (TOML `[[name]]`): typed loading into `Vec<T>`, per-entry defaults, per-entry required/type checks and strict unknown-key detection with indexed paths (`plugins[1].rogue`), commented array-of-tables template example, and JSON Schema `items` all work through the existing walkers. `FieldStatic::ArrayOf` is now a struct variant carrying the field-site `///` doc (parity with `Nested`/`MapOf`).
  - Support is **trait-resolved, not syntactic**: the macro emits `<T as Schema>::STATIC` and the *compiler* decides whether the element type qualifies — any type deriving `Schema` works, and a non-qualifying element (`Vec<PathBuf>`) fails with the trait's `on_unimplemented` guidance naming the `#[clapfig(value)]` escape hatch.
  - Enum-vs-object distinction: `Vec<UnitEnum>` flattens converter-side to a `LeafType::Array(Enum)` leaf — the array sibling of WS02's `Map(Enum)` flatten — so entries validate against the variant set, the template emits the `# Allowed:` line, and the JSON Schema carries `enum` on the `items` schema. This lands the mechanism behind the postponed #101/#102.
  - `Option<Vec<UnitEnum>>` keeps the presence signal (absent → `None`). `Option<Vec<NestedStruct>>` has no representation (absence is already the empty array) and fails at the first `schema()` call with drop-the-`Option` guidance — deferred like the other enum-vs-struct kind checks, since the macro cannot resolve the element kind.
  - Absence rule unified with maps (**behavior change**): an absent array is the empty array. Structural `ArrayOf` nodes and non-optional array-typed *leaves* without a declared default (including plain `Vec<String>`-style fields, previously a `MissingRequired` error) now materialize `[]` before the typed deserialize, and array-typed leaves are no longer listed as `required` in the generated JSON Schema. Templates use the same rule: a non-optional array or map leaf no longer carries a `Required.` line (absence is already `[]`/`{}`). A declared `#[clapfig(default = [...])]` still wins over the empty-array materialization.
  - Defaults on array-of-nested fields are rejected at derive time (same rule and rationale as map-of-nested fields: entries are user-supplied), as are `env`/`allowed`/`optional`. Remaining unsupported constructs (`Vec<Vec<...>>`, `Vec<Option<T>>`, `Vec<clapfig::value::Value>`, maps of arrays of schema types) keep derive-time errors naming the `#[clapfig(value)]` escape hatch.
