- **Derive hardening: silent-wrong `#[derive(clapfig::Schema)]` behaviors fixed or rejected** ([#131](https://github.com/arthur-debert/clapfig/issues/131), DER01-WS02) — Every audited case where the derive compiled but produced a schema that disagreed with serde or lost information is now either correct or a derive-time error. **Breaking on purpose**: code relying on the newly-rejected constructs was already silently misbehaving; there is no compatibility path.
  - Fixed: `HashMap<String, UnitEnum>` / `BTreeMap<String, UnitEnum>` now flattens to `LeafType::Map(Enum)` — previously it emitted a `MapOf` of an empty schema and every entry failed at load with "expected map, got string" (map-shaped sibling of the `Nested` enum flatten).
  - Fixed: raw identifiers unraw — a field `r#type` (or variant `r#Try`) now emits serde's spelling (`type`/`Try`) instead of `r#type`, which no config key could ever match.
  - Fixed: field-site `///` docs on bare nested-struct, unit-enum, and map-of-nested fields are retained (field doc wins over the referenced type's doc; previously dropped, asymmetric with `Option<Enum>`). `FieldStatic::Nested`/`MapOf` are now struct variants carrying the field-site doc.
  - Fixed: `Vec<clapfig::value::Datetime>` array defaults emit datetime-typed elements (previously string-typed, rejected by the leaf's own type check at first `schema()` call).
  - New derive-time errors: duplicate schema field names after renames; invalid rename strings (empty, or containing `.`/`[`/`]`); unknown `#[clapfig(...)]` metas on enum variants (previously silently skipped); conflicting variant-level clapfig/serde renames (previously clapfig silently won); `#[clapfig(name)]`/`#[clapfig(strict)]` on unit-only enums (accepted then discarded at flatten); kind-mismatched `default` literals (checked like `allowed`, per element for arrays, and against the `allowed` set when both are present); defaults on map-typed fields.
  - Reject-loudly serde policy (epic DER01 decision): every serde attribute the schema does not honor — `default`, `flatten`, `alias`, `skip`, `skip_deserializing`, `tag`/`untagged`/`content`, `deny_unknown_fields`, `transparent`, `from`/`try_from`, … — is a derive-time error naming the attribute and the divergence it would cause. Honored and serialize-only/plumbing attributes (`rename`, unit-enum `rename_all`, `deserialize_with`/`with`, `skip_serializing*`, `serialize_with`, `bound`, `borrow`, `crate`, `expecting`) remain accepted.
  - Lookalike guard: field types merely *named* `Datetime`/`Value` are claimed by name (a proc macro can't resolve paths), so the derive now emits a compile-time `IsClapfigDatetime`/`IsClapfigValue` assertion — a user's own `struct Datetime` is a compile error with guidance instead of a silently mis-typed datetime leaf.
  - Enum-typed field defaults (`#[clapfig(default = "variant")] mode: Mode`) are checked against the variant set at first `schema()` call; a non-variant default panics with a message naming the field and the variant list.
  - Diagnostics: the `clapfig::Schema` trait carries `#[diagnostic::on_unimplemented]`, so unsupported field types (PathBuf, Duration, char, newtypes, …) produce a message naming the supported scalar set and the `#[clapfig(value)]` escape hatch instead of a raw E0277.
