- **Added**
  - **Typed tree-walk resolver** ([#135](https://github.com/arthur-debert/clapfig/issues/135), part of DER01 [#129](https://github.com/arthur-debert/clapfig/issues/129)) — `TypedBuilder::build_resolver()` returns the new `TypedResolver<C>`, restoring the typed tree-walk surface #105 removed (its changelog named this the candidate follow-up). The handle wraps the Map-out `Resolver` — same per-call `Cwd`/`Ancestors` anchoring, same no-mtime file cache, built clone-free from the derive's cached `Arc<Schema>` — and each `resolve_at(dir)` call deserializes the merged map into a typed `C` and runs the typed `post_validate(&C)` hook. `resolve_at_with_unknowns` mirrors `load_with_unknowns`. New public export: `TypedResolver`.
- **Changed**
  - **`config set` parses values by the declared leaf type** ([#135](https://github.com/arthur-debert/clapfig/issues/135)) — the raw string is no longer sniffed env-style before the schema is consulted. A `String` leaf takes `123` verbatim (previously "expected string, got integer" with no way to force a string); `Integer`/`Float`/`Bool` leaves parse as that type and refuse naming the expected type; `Array`/`Map` leaves — previously entirely unsettable — accept TOML inline syntax (`["a", "b"]`, `{cpu = 2}`, the value model's baseline vocabulary regardless of the file's format), with element types still checked; enum members keep their own types, with numeric-looking string members now reachable. `Value` leaves keep the heuristic (no declared shape to parse toward).
  - **Targeted error for array/map section paths in `config set`** ([#135](https://github.com/arthur-debert/clapfig/issues/135)) — `config set servers.web.host x` against a map-of-sections field (`Shape::Map` of objects, same for `Shape::Array`) now fails with the new `ClapfigError::UnaddressableKey` naming the section and explaining that keys inside array/map sections can't be addressed with a dotted CLI key (edit the config file directly), instead of a bare `Key not found`. Indexed path syntax remains a future feature.
  - **`ConfigResult` display is format-aware** ([#135](https://github.com/arthur-debert/clapfig/issues/135)) — `config get`/`list`/`set` output renders in the active format's spelling instead of always TOML-style: `key = value` under TOML, `key: value` under YAML, `"key": value` under JSON, with doc comments as `#` lines (TOML/YAML) or `//` lines (JSON). The `KeyValue`/`Listing`/`ValueSet` variants gain a `rendered` field carrying that display block (spelled by the new `FormatAdapter::display_entry`/`display_comment` presentation methods); the structured fields are unchanged. The active format is the scope file's for scoped operations and the preferred format for merged views.
  - **Env flat-vs-nested doc fix** ([#135](https://github.com/arthur-debert/clapfig/issues/135)) — the env layer's docs now state last-writer semantics for a key set both flat (`MYAPP__DATABASE`) and nested (`MYAPP__DATABASE__URL`): environment iteration order is unspecified, so no winner is promised — don't mix the shapes.
- **Tests** (guard restorations from the FIXME.md audit — behavior was already correct, the tests had been dropped by later refactors)
  - `add_search_path` preserves the default `Platform` path when it is the first path call, and appends to an explicitly-set list (FIXME #1/#10; deleted by #105).
  - An unreadable (permission-denied) config file surfaces `ClapfigError::IoError` naming the file — on load and on `config set` — rather than being silently skipped like a missing file (FIXME #13; deleted by an earlier resolver refactor).
  - New integration coverage for the previously untested typed surfaces: `TypedBuilder::load_with_unknowns`, `TypedResolver::resolve_at`/`resolve_at_with_unknowns` (anchoring, caching, typed post_validate).
