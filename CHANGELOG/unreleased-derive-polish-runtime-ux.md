- **Changed**
  - **Runtime UX sweep: templates, error rendering, JSON Schema fidelity, integer bounds** ([#134](https://github.com/arthur-debert/clapfig/issues/134), part of DER01 [#129](https://github.com/arthur-debert/clapfig/issues/129)) —
    - **Templates (`config gen`)**: required-defaultless leaves carry a `Required.` annotation in all three formats (previously they rendered identically to optional placeholders, so users generated a template, didn't uncomment, and failed with `MissingRequired`); array/map placeholders (`[]`/`{}`) carry an `Elements:`/`Values:` element-type hint.
    - **Integer-for-float coercion**: `timeout = 5` on an `f64` field loads (serde always accepted it; the schema check no longer rejects it first). The merged value is coerced to `Value::Float` during finalization — schema-driven, like the ADR-0001 datetime coercion — so Map-out consumers and `config get` see a float too (`schema_walk::coerce_datetime_value` is now `coerce_value`).
    - **Error rendering**: YAML/JSON unknown-key errors no longer render a bogus `(line 0)` / `--> config.yaml:0` (the line is omitted when it can't be located; real YAML/JSON line numbers are the provenance epic's). Env-derived unknown keys render as env errors naming the exact variable to unset (`MYAPP__ROGUE_KEY`) instead of wearing config-file clothing — `UnknownKeyInfo` gains `env_var: Option<String>`, and `on_unknown_key` callbacks now see `file: None` for env-sourced keys (previously a synthesized `<env>` path). Omitting `Layer::Env` from `layer_order` skips env construction and unknown-key validation, so `APP__ROGUE` no longer fails when the env layer is excluded. A deserialize failure inside a typed `post_validate` hook is categorized as the `InvalidValue` type error it is, not `PostValidationFailed` wearing a bare serde message — on `load`/`TypedResolver` and on merged `config get`/`list` via typed `handle`. `KeyNotFound` is now a struct variant carrying an optional near-miss `suggestion` (`Key not found: db.pool_sizr — did you mean 'db.pool_size'?`; new public `meta::nearest_key`). Scoped `config get` against a scope whose file doesn't exist fails as the new `ScopeFileMissing { scope, path }` instead of claiming the key doesn't exist.
    - **JSON Schema export**: leaf-container conversion is recursive — nested arrays keep inner `items`, `Array(Enum)` keeps the enum constraint on items, `Map(elem)` constrains entry values via `additionalProperties` (with the ADR-0002 `^//` comment-key allowlist). `required` now mirrors what the runtime rejects when absent: a leaf only if non-optional AND defaultless, a section only if it transitively contains one (previously every section and every non-optional leaf was required, so external validators rejected configs clapfig loads fine). Datetime leaves export `type: string` plus an `anyOf` covering TOML's four lexical forms: range-aware patterns (month/day/hour/minute/second/offset) so `1979-99-99` is not accepted, with `format: "date-time"` / `"date"` only on the branches those formats describe; datetime defaults emit in lexical string form instead of being dropped. Heterogeneous `Enum` sets omit a single inferred `type` so `enum` alone constrains mixed primitives. Unrepresentable values (non-finite floats — JSON has no literal for them) omit the complete `default` / `enum` annotation rather than dropping individual members and exporting a narrowed set.
    - **Integer bounds**: `LeafType::Integer` / `LeafTypeStatic::Integer` carry `min`/`max` bounds; the derive macro emits each Rust width's range (`u8` → `0..=255`; `i64` unbounded; `isize` uses `isize::MIN/MAX as i64`; `u64` min 0, open top; `usize` min 0 with a maximum only when `usize::BITS < 64`), the runtime check rejects out-of-range values naming the key path (`u8 = 300` no longer sails through to a `<merged>` serde failure), and the JSON Schema export carries the bounds as `minimum`/`maximum`. New runtime builder `Field::integer_in(min, max)` (panics if both ends are set and `min > max` — an authoring error, same class as a duplicate field name).
