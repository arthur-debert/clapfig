- **Changed**
  - **Structural collapse of the two-path era + hard rename sweep** ([#130](https://github.com/arthur-debert/clapfig/issues/130), part of DER01 [#129](https://github.com/arthur-debert/clapfig/issues/129)) — The crate has one schema model (`runtime::Schema`); the bridge-era mirror that half the code still walked is gone. Internally: the `SchemaRef`/`FieldRef`/`FieldKindRef`/`LeafRef` view types and the single-implementation `ConfigSpec` trait (with its `DynamicSpec` newtype) are deleted; every consumer — metadata lookup, JSON Schema emission, strictness cascade seeding, valid-key enumeration, unknown-key validation — walks `&runtime::Schema` directly (superseded by SHP01: walkers take `Shape`; `Schema` stays the object constructor), and the resolve pipeline holds the schema instead of a generic spec. The two ~65-line unknown-key walkers (per-file and env-layer) are now one walker serving both layers; the env layer gains harmless `ArrayOf` recursion (env dotted keys can't build arrays-of-tables, so no behavior change). Pure structural collapse: behavior unchanged except the renames below (pre-1.0, no aliases per project rule). Public renames, on the Map-out vs typed-out axis (bare name = Map-out, `Typed` prefix = typed-out):
    - `RuntimeBuilder` → `Builder`; entry point `Clapfig::runtime(schema)` → `Clapfig::builder(schema)`
    - `RuntimeResolver` → `Resolver`
    - `SchemaConfigBuilder<C>` → `TypedBuilder<C>`; entry point `Clapfig::schema_builder::<C>()` → `Clapfig::typed::<C>()`
    - `meta::doc_for_runtime` → `meta::doc_for`
    - module `clapfig::schema` → `clapfig::json_schema` (the JSON Schema emitter; "schema" alone collided with the derive trait and the data model)
