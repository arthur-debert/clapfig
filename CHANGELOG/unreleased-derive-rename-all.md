- **Struct-level `rename_all` in `#[derive(clapfig::Schema)]`** ([#107](https://github.com/arthur-debert/clapfig/issues/107), [#133](https://github.com/arthur-debert/clapfig/issues/133), DER01-WS04) — `#[serde(rename_all = "...")]` / `#[clapfig(rename_all = "...")]` on a struct is now honored instead of rejected: the derived schema converts every field name (fields without an explicit rename) with serde-exact semantics — `serde_derive`'s `RenameRule::apply_to_field`, snake_case source — so schema names, strict validation, templates, JSON Schema, and the typed deserialize all agree on the converted spellings. Full rule set: `lowercase`, `UPPERCASE`, `PascalCase`, `camelCase`, `snake_case`, `SCREAMING_SNAKE_CASE`, `kebab-case`, `SCREAMING-KEBAB-CASE`, including serde's digit behavior (`render_2d` → `Render2d`) and identity `lowercase`/`snake_case`.
  - Precedence matches serde: explicit `#[clapfig(rename)]`/`#[serde(rename)]` wins over the rule; a serialize-only directional field rename is invisible to the deserialize side, so the rule still applies there. The directional `rename_all(deserialize = "...")` form contributes its deserialize rule; a serialize-only `rename_all(serialize = "...")` stays accepted and inert.
  - Converted names run through the same derive-time validation as explicit renames (non-empty, no `.`/`[`/`]`) and the post-rename duplicate check.
  - New derive-time errors: an unsupported rule string (lists the supported set), and a clapfig/serde `rename_all` pair naming different rules (same contract as conflicting field renames).
  - Boundary: a `kebab-case` schema is incompatible with the builder's `normalize_keys(true)` mode (which canonicalizes incoming keys to snake_case) — the combination fails strict validation loudly rather than silently mis-loading; pick one convention.
