**Located post-merge errors** ([#151](https://github.com/arthur-debert/clapfig/issues/151), epic [#146](https://github.com/arthur-debert/clapfig/issues/146)) — the origin shadow tree now travels in lockstep with the value tree through file parse, env, URL, overrides, `deep_merge`, and `fill_defaults_into` (ADR-0004). Schema-driven errors on a value that exists (`InvalidValue`) name the winning origin.

- **File**: path + line from the **value** span; renderers caret that range. `normalize_keys(true)` still reaches the source span, so the snippet shows the user's spelling.
- **Env**: original variable name, keyed by `ConfigPath` so a MapOf entry with a literal `.` (`APP__PLUGINS__A.CONFIG__X`) is distinct from genuine nesting (`APP__PLUGINS__A__CONFIG__X`). **URL**: query-parameter key as received (dotted, percent-decoded). **Override**: the override key. **Default**: schema key (a declared default that fails the leaf's type or enum check).
- Coercion in `finalize` (datetime strings, integer-for-float) does **not** change origin. Arrays replace wholesale in `deep_merge`; the origin subtree replaces wholesale with them. `"a.b"` vs `[a] b` are distinct origin identities.
- `MissingRequired` still carries the discovery record, not an origin. `PostValidationFailed` stays an opaque string.
