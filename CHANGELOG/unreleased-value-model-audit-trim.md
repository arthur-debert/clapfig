**Value-model surface trim** ([#123](https://github.com/arthur-debert/clapfig/issues/123), epic [#110](https://github.com/arthur-debert/clapfig/issues/110)) — pre-merge trim of overbuild found by the epic's code audit. No behavior changes; three public-surface cuts (hard cuts, per project policy):

- **`Datetime` is now `toml_datetime`'s** (`Date`/`Time`/`Offset`/`DatetimeParseError` too, re-exported from `clapfig::value` as before). Same four TOML 1.0 lexical forms, same RFC 3339 grammar and nanosecond truncation, same `Display` spellings, so parse/display behavior is unchanged. The hand-rolled type's validating component constructors (`Date::new`, `Time::new`, `Offset::custom`, the four form constructors) and accessor methods are gone — the fields are public on `toml_datetime`'s types. Two consequences of that swap, both part of the hard cut:
  - **Trait surface**: `Datetime`/`Date`/`Time`/`Offset` no longer implement `Hash` (they gain `Ord`/`PartialOrd`; use the `Display` string as a hash key if you hashed these), and `DatetimeParseError` no longer implements `PartialEq`/`Eq` (compare its `Display` output if you compared parse errors).
  - **Construction contract**: validation happens at parse time only (`FromStr` enforces the same ranges, leap rules, and offsets as before). Because the component fields are public, safe code *can* assemble a non-grammatical value (e.g. month 13); clapfig adopts the toml ecosystem's own contract for those — garbage in, garbage out (a serialize error or a non-grammatical spelling in output), never a panic. Values that travel the normal parse path are validated exactly as before.

  `toml_datetime` is a standalone type crate, not a format crate (ADR-0001 amended).
- **The speculative provenance surface is gone until the provenance epic needs it**: `PathSegment::Index` and `ConfigPath::index` are removed (paths address map keys only), and the `SpanIndex` container is replaced by a plain `BTreeMap<ConfigPath, Span>` return on the retained `FormatAdapter::span_index` seam. `Span` and `Operation::SpanIndex` are unchanged. (Superseded by PRV01: `PathSegment::Index` returned and `parse` fills `{value, spans}`.)
- Internal: the `string_only_serializer!` macro (~170 lines) collapsed into a two-arm match over the existing value serializer; identical behavior for map keys and datetime marker extraction.
