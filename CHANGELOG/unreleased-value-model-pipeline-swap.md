**The pipeline swap: clapfig speaks its own value model** ([#112](https://github.com/arthur-debert/clapfig/issues/112), epic [#110](https://github.com/arthur-debert/clapfig/issues/110)) — The core pipeline (layer construction, merge, defaults, validation, resolved output, schema defaults/enum sets) now traffics in the owned `clapfig::value::Value` / `clapfig::value::Map` model; `toml`/`toml_edit` are confined to the TOML format adapter behind the `clapfig::format` contract. Every file read and write — discovery parsing, template generation, persistence edits, file seeding — dispatches through the adapter registry. TOML-path behavior is regression-locked (generated templates are byte-identical, golden-tested); the refactor is invisible unless you touch one of the renamed public types below. Also new, per the value-model spec:

- **Builder file contract**: `.file_name("myapp.toml")` keeps exact-name discovery (that name's format only; extensionless names still parse as TOML). New `.file_stem("myapp")` + `.formats(["toml", ...])` probe the stem across the enabled formats' extensions — ordered, opt-in, default TOML only; two same-stem files in one directory are a hard `AmbiguousConfigFiles` error, and an empty or repeating `formats(...)` list is a hard `InvalidFormats` error. The first enabled format is the preferred format: stdout `config gen` renders it, and file-creating `config set` seeds `<stem>.<preferred extension>` from the template. Explicit paths (persist targets, `gen --output`) select their adapter by extension, independent of the enabled list; a file name or explicit path with an extension no adapter claims (e.g. `config.ini`) is a hard `UnknownFormat` error — never a silent TOML fallback.
- **Schema-driven datetime coercion** (ADR-0001): for leaves declared `DateTime`, string values from schema-blind sources (env vars, CLI/URL overrides, `config set`, future YAML/JSON files) are parsed against TOML's four datetime lexical forms; a string matching none of them is a normal type error. Never value-sniffing — only declared datetime leaves coerce.
- **Hack deletions**: the derive path's serialize-reparse datetime round trip (the serde bridge deserializes `Value` directly) and the `toml_value_to_json` boundary converter (JSON Schema export converts from the owned model).

**Migration (hard cut, per project policy):**

- `Clapfig::runtime(...).load()` / `load_with_unknowns()` / `RuntimeResolver::resolve_at*` return `clapfig::value::Map` (a `BTreeMap<String, clapfig::value::Value>`) instead of `toml::Table`. `Value` keeps the familiar accessors (`as_str`, `as_integer`, …) with `as_map` replacing `as_table`, plus `Index<&str>`/`Index<usize>`. Deserialize a map into a typed struct with `clapfig::value::from_value(Value::Map(map))`.
- The runtime `post_validate` hook receives `&clapfig::value::Map` instead of `&toml::Table`. (The typed `SchemaConfigBuilder::post_validate` still receives `&C`.)
- Schema value slots — `Field::default(...)`, `Field::enum_of(...)`, `runtime::Leaf::default`, `LeafType::Enum { values }` — hold `clapfig::value::Value` instead of `toml::Value`. `From` impls keep literal call sites (`.default(8080i64)`, `.enum_of(["a", "b"])`) source-compatible.
- Derive field types: `toml::Value` → `clapfig::value::Value` (for `#[clapfig(value)]`-style free-form leaves) and `toml::value::Datetime` → `clapfig::value::Datetime`. The derive no longer recognizes the `toml` spellings.
- `UnknownKeyContext::value` and `CollectedUnknown::value` carry the owned `clapfig::value::Value`.
- `ClapfigError::ParseError::source` is now the adapter's `clapfig::format::FormatError` (carrying the parse span) instead of `toml::de::Error`; `ClapfigError::parse_error()` returns it accordingly. New variants: `Format` (adapter refusals/failures outside file parsing), `UnknownFormat`, `InvalidFormats`, `AmbiguousConfigFiles` — `ClapfigError` is `#[non_exhaustive]`, so existing `match`es with a catch-all arm keep compiling.
- `config set`/`unset` edit failures (e.g. a path conflict through an existing scalar) surface as `ClapfigError::Format` carrying the adapter's typed `FormatError`, instead of being collapsed into `InvalidValue`; `InvalidValue` remains the schema/type-validation error.
- `static_schema::ValueStatic::to_toml()` → `to_value()`, returning `clapfig::value::Value`.
